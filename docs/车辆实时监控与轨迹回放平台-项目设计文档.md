# 车辆实时监控与轨迹回放平台 — 项目设计文档

> 一个面向「自动驾驶 / 车联网」场景的学习型项目，模拟「车端 → 云端 → 监控大屏」完整数据链路。
> 目标：在 React + SpringBoot 技术栈下，做出一个有技术深度（实时通信 / 时序存储 / 地理围栏 / 轨迹回放）且贴合业务的作品级项目。

---

## 1. 项目概述

### 1.1 背景与目标
- **业务背景**：自动驾驶 / 车联网的基础能力是车端遥测数据的实时采集、上报、存储与可视化监控。
- **项目目标**：用一套可本地运行的系统，完整复刻「多车实时上报 → 后端接入聚合 → 时序落库 → 大屏实时监控 → 历史轨迹回放 → 告警」的链路。
- **非目标**：不做真实硬件接入，不做高精地图 / 自动驾驶决策算法。车端用「模拟器」代替。

### 1.2 核心功能清单
| 编号 | 功能 | 说明 | 优先级 | 状态 |
|---|---|---|---|---|
| F1 | 车辆管理 | 车辆台账 CRUD、在线/离线状态 | P0 | ✅ 已实现 |
| F2 | 实时位置监控 | 地图上多车实时移动（WebSocket 推送） | P0 | ✅ 已实现 |
| F3 | 实时指标大屏 | 在线数、速度分布、电量、告警统计（ECharts） | P0 | ⚪ 基础版已实现（无 ECharts） |
| F4 | 历史轨迹回放 | 选车 + 选时间段，拖动时间轴回放路线 | P0 | ❌ M3+ |
| F5 | 告警与地理围栏 | 超速 / 低电量 / 驶出围栏触发告警 | P1 | ❌ M4+（表已创建） |
| F6 | 用户与权限 | 登录、JWT、RBAC（管理员/观察员） | P1 | ✅ 已实现 |
| F7 | 轨迹抽稀与平滑 | 道格拉斯-普克算法压缩轨迹点 | P2 | ❌ M3+ |
| F8 | 告警事件流 | Kafka 异步处理告警（进阶） | P2 | ❌ M5+ |

### 1.3 技术栈（已选型）
- **前端**：React 18 + TypeScript + Vite + Zustand + React Router + Tailwind CSS 4 + **高德地图 JS API（见 §2.4）**
- **后端**：JDK 17 + SpringBoot 3.5 + MyBatis-Plus + Spring Security + JWT + spring-integration-mqtt(Paho)
- **中间件**：EMQX（MQTT Broker）+ TimescaleDB（PostgreSQL + 时序，含 PostGIS）+ Redis
- **进阶**：Kafka（告警事件流，M5+）
- **部署**：Docker Compose（一键起全套）

### 2.4 地图方案：高德（AMap JS API）

> 地图统一使用 **高德 JS API**。选高德的原因：贴近国内车联网真实项目，国内路网/POI/逆地理编码准确，且自带 `AMap.MoveAnimation` 轨迹动画，车标沿路线平滑移动的效果开箱即用。

**接入准备**：
- 在 [高德开放平台](https://lbs.amap.com/) 申请 **Web端(JS API) Key + 安全密钥 securityJsCode**（你已有 Key）。
- 前端通过 `@amap/amap-jsapi-loader` 动态加载 SDK，Key/securityJsCode 放在 `.env` 环境变量里（不硬编码、不入仓）。

**地图能力映射到本项目功能**：
| 需求 | 高德 API |
|---|---|
| 车辆实时位置 | `AMap.Marker` + 定时 `setPosition` 更新 |
| 车标平滑移动 | `AMap.MoveAnimation`（`moveAlong` 沿轨迹点动画） |
| 轨迹回放 | `AMap.Polyline` 画线 + `moveAlong` 按时间轴重放，支持倍速/暂停 |
| 地理围栏绘制 | `AMap.Polygon` 展示围栏区域 |
| 告警标记 | `AMap.Marker` + 自定义图标/InfoWindow |

**坐标系注意（重要）**：高德用 **GCJ-02（火星坐标）**。若车辆模拟器/数据库里存的是 **WGS-84（GPS 原始坐标）**，前端上图前必须做 `wgs84 → gcj02` 转换（用 `coordtransform` 库），否则车会整体偏移几百米。建议直接让模拟器生成 GCJ-02 坐标，源头统一、免去转换麻烦。

## 3. 模块拆解

### 3.1 车辆模拟器（simulator）
- **职责**：模拟 N 辆车，按固定频率（如 1s）沿预设路线移动并通过 MQTT 上报遥测。
- **关键点**：
  - 预设若干条路线（一组经纬度点），车辆沿路线插值前进，速度随机波动。
  - 偶发异常：随机注入超速、急刹、低电量，用于触发告警。
  - 发布到 topic：`vehicle/{vehicleId}/telemetry`，payload 为 JSON。
- **实现**：可作为 SpringBoot 内的 `@Scheduled` 任务，或独立 Java/Node 小程序。建议独立，便于压测时多开。

### 3.2 数据接入服务（telemetry ingest）
- **职责**：订阅 MQTT `vehicle/+/telemetry`，解析消息后：
  1. 更新 Redis 实时状态（最新位置/速度/电量/在线时间）
  2. 异步批量写入 TimescaleDB 遥测表（轨迹）
  3. 调用告警引擎做规则判定
  4. 通过 WebSocket 广播实时位置
- **关键点**：写库用逐条 INSERT + 节流广播（每 500ms 聚合一次全量车辆位置再推），避免高频单条写入压垮 DB 和前端；在线判定用 Redis TTL（10s 无上报判离线）。

### 3.3 存储层
- **Redis**：实时态（哈希）、在线集合、最新告警。
- **TimescaleDB**：遥测时序（hypertable）、车辆/告警/围栏/用户等关系表，围栏用 PostGIS geometry。

### 3.4 推送服务（ws）
- **职责**：基于 STOMP，向订阅 `/topic/vehicles` 的客户端广播实时位置批次；向 `/topic/alerts` 广播告警。
- **关键点**：广播做节流（如每 500ms 聚合一次全量车辆位置再推），避免逐条推送压垮前端。

### 3.5 告警与地理围栏（alert）
- **规则**：超速（speed > 阈值）、低电量（battery < 阈值）、驶出围栏（PostGIS `ST_Contains` 判定点是否在围栏多边形内）。
- **进阶**：告警先入 Kafka，消费端落库 + 推送，解耦削峰。

### 3.6 轨迹回放（track）
- **职责**：按 vehicleId + 时间范围查询轨迹点，返回给前端回放。
- **关键点**：
  - 点多时用 **道格拉斯-普克算法** 抽稀（后端或 PostGIS `ST_Simplify`）。
  - 前端按时间轴插值平滑移动游标，支持倍速 / 暂停 / 拖动。

### 3.7 认证与权限（auth）
- 登录返回 JWT；Spring Security 过滤器校验；RBAC 两个角色：`ADMIN`（增删改）/`VIEWER`（只读监控）。

## 4. 数据库表结构设计（TimescaleDB / PostgreSQL）

### 4.1 车辆表 `vehicle`
```sql
CREATE TABLE vehicle (
    id           BIGSERIAL PRIMARY KEY,
    plate_no     VARCHAR(32)  NOT NULL UNIQUE,   -- 车牌
    vin          VARCHAR(32),                     -- 车架号
    model        VARCHAR(64),                     -- 车型
    status       SMALLINT DEFAULT 0,              -- 0离线 1在线
    created_at   TIMESTAMPTZ DEFAULT now(),
    updated_at   TIMESTAMPTZ DEFAULT now()
);
```

### 4.2 遥测时序表 `telemetry`（Hypertable）
```sql
CREATE TABLE telemetry (
    time         TIMESTAMPTZ      NOT NULL,
    vehicle_id   BIGINT           NOT NULL,
    lng          DOUBLE PRECISION NOT NULL,
    lat          DOUBLE PRECISION NOT NULL,
    speed        REAL,            -- km/h
    heading      REAL,            -- 航向角 0-360
    battery      REAL,            -- 电量 %
    fault_code   VARCHAR(32),     -- 故障码
    geom         GEOMETRY(Point, 4326)  -- PostGIS 点，便于空间查询
);
-- 转为时序超表，按时间自动分区
SELECT create_hypertable('telemetry', 'time');
CREATE INDEX idx_telemetry_vehicle_time ON telemetry (vehicle_id, time DESC);
CREATE INDEX idx_telemetry_geom ON telemetry USING GIST (geom);
```

### 4.3 地理围栏表 `geo_fence`
```sql
CREATE TABLE geo_fence (
    id        BIGSERIAL PRIMARY KEY,
    name      VARCHAR(64) NOT NULL,
    type      SMALLINT,                         -- 0禁行区 1限速区
    area      GEOMETRY(Polygon, 4326) NOT NULL, -- 围栏多边形
    speed_limit REAL,
    enabled   BOOLEAN DEFAULT true,
    created_at TIMESTAMPTZ DEFAULT now()
);
CREATE INDEX idx_geofence_area ON geo_fence USING GIST (area);
```

### 4.4 告警表 `alert`
```sql
CREATE TABLE alert (
    id          BIGSERIAL PRIMARY KEY,
    vehicle_id  BIGINT NOT NULL,
    type        VARCHAR(32) NOT NULL,   -- OVERSPEED / LOW_BATTERY / OUT_OF_FENCE
    level       SMALLINT DEFAULT 1,      -- 1提示 2警告 3严重
    message     VARCHAR(255),
    lng         DOUBLE PRECISION,
    lat         DOUBLE PRECISION,
    occurred_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    handled     BOOLEAN DEFAULT false
);
CREATE INDEX idx_alert_vehicle_time ON alert (vehicle_id, occurred_at DESC);
```

### 4.5 用户 / 角色（RBAC）
```sql
CREATE TABLE sys_user (
    id        BIGSERIAL PRIMARY KEY,
    username  VARCHAR(64) NOT NULL UNIQUE,
    password  VARCHAR(128) NOT NULL,          -- BCrypt
    role      VARCHAR(32) NOT NULL DEFAULT 'VIEWER',  -- ADMIN / VIEWER
    enabled   BOOLEAN DEFAULT true,
    created_at TIMESTAMPTZ DEFAULT now()
);
```

### 4.6 Redis 键设计
| Key | 类型 | 内容 | TTL | 说明 |
|---|---|---|---|---|
| `vehicle:rt:{id}` | Hash | lng,lat,speed,heading,battery,ts | 10s | 车辆最新实时态，过期即判离线 |
| `vehicle:online` | Set | vehicleId 集合 | — | 在线车辆集合，定时清理过期 |
| `vehicle:meta:{id}` | String | plateNo,status | 24h | 车辆基础元数据缓存（防击穿，Cache-Aside） |
| `alert:latest` | List | 最近 N 条告警 JSON（M4+） | — | 大屏告警滚动 |

## 6. 关键技术难点（你的"深度"亮点）

1. **MQTT → WebSocket 桥接**：协议转换 + 节流聚合广播，避免前端被高频消息压垮。
2. **时序写入优化**：高频遥测的批量缓冲写入 + Timescale Hypertable 自动分区 + 连续聚合（continuous aggregate）做大屏统计预聚合。
3. **地理围栏**：PostGIS `ST_Contains` 实时判定点是否在多边形内，超速/越界告警。
4. **轨迹抽稀**：道格拉斯-普克算法（或 `ST_Simplify`）压缩海量轨迹点，前端流畅回放。
5. **回放时间轴**：前端按真实时间戳插值，支持倍速/暂停/拖动游标。
6. **在线判定**：Redis TTL 心跳机制。
7. **（进阶）Kafka 削峰**：告警/遥测走 Kafka 异步消费，多车压测下保证不丢不卡。
